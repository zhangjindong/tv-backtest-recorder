## 1. 一句话目标

在 TradingView 网页版做 K 线回放时，**在仓位工具上点一下**，就把这一笔的
**方向、开仓价、止损价、止盈价、品种、周期、当时截图**复制走，`Ctrl+V` 直接进自己的 Excel 台账。

## 2. 插件边界（v1.2 冻结）

### 插件负责（P0）

| 编号 | 需求 |
|---|---|
| R1 | 自动读取仓位工具：**方向 / 开仓价 / 止损价 / 止盈价**；图上被**隐藏**的工具不列出 |
| R2 | 抓取当时的图表截图，**连同数据一起进剪贴板**（不落盘、不写路径） |
| R3 | **点击触发**：在面板上点一下就能复制（核心交互） |
| R4 | 剪贴板同时放 `text/plain`（TSV）与 `text/html`（表格 + 内嵌截图），`Ctrl+V` 进 Excel 自动分列、自动追加 |
| R5 | 记录本地留存，可复查、可删除 |
| R6 | 「复制全部未导出」，避免重复粘贴 |

### 明确不做（转 Excel 手填）

| 项 | 归属 |
|---|---|
| T1 / T2 / T3 三个目标位 | **Excel 手填**（插件只给仓位工具里的那一个 TP） |
| 踏空标记 | **Excel 手填** |
| 手数 / 分批比例 | **Excel 手填** |
| 结果（止盈 / 止损） | **Excel 手填** |

→ 插件输出的是**这一笔的客观事实**（价格、时间、图），主观判断全留给码哥。

## 3. 技术可行性 · 实测报告

> 2026-09-26 对 tradingview.com 真实页面 CDP 注入实测。环境：Chrome 152，匿名访问。

### 3.1 网页版暴露完整官方 Chart API

```js
window.TradingViewApi.activeChart()
  .getAllShapes()               // [{id, name}] → name ∈ {long_position, short_position}
  .getShapeById(id)
    .getPoints()                // [{price, time}] → 开仓价
    .getProperties()            // {stopLevel, profitLevel, qty, lotSize, ...}
chart.chartModel().mainSeries().symbolInfo()   // { pricescale: 100, minmov: 1 }
```

### 3.2 提取公式（实测交叉验证通过）

```
tick   = minmov / pricescale
开仓价 = getPoints()[0].price
多头:  止损 = 开仓价 − stopLevel   × tick     止盈 = 开仓价 + profitLevel × tick
空头:  止损 = 开仓价 + stopLevel   × tick     止盈 = 开仓价 − profitLevel × tick
```

| 验证项 | 实测值 |
|---|---|
| 开仓价 / stopLevel / tick | 312.59 / 2038 / 0.01 |
| 公式算出止损 | 312.59 − 20.38 = **292.21** |
| `getRawPoints()` 实测止损 | **292.21** ✅ |
| 改盈亏比后 qty | 100 ÷ (1000×0.01) = 10，实测 **10** ✅ |

### 3.3 已排除的坑

| 坑 | 实测表现 | 对策 |
|---|---|---|
| `getRawPoints()` 数据不全 | long 给 4 点（含止损），short 只给 2 点 | 主用 `getProperties()` 公式；rawPoints 仅作交叉校验 |
| `_chartWidgetCollection.takeScreenshot()` | 返回 8 字符任务 ID，拿不到图 | 改用 `chrome.tabs.captureVisibleTab()` |

### 3.4 隐藏工具的可见性判定（v1.4 新增）

**需求**：图上的多单 / 空单被**隐藏**后，面板不应再列出来。

**查证**：`ILineDataSourceApi`（即 `getShapeById()` 的返回类型）官方方法表里**没有 `isVisible`** ——
只有 `getPoints / setPoints / getProperties / setProperties / isSelectionEnabled / isSavingEnabled /
isShowInObjectsTreeEnabled / isUserEditEnabled / bringToFront / sendToBack` 等。
`setEntityVisibility(id, isVisible)` 已被官方标记废弃，且**没有配套 getter**。

**对策**：多路兜底（`tv-bridge.js` → `resolveVisible`），按优先级取第一个能用的：

| 优先级 | 路径 | 说明 |
|---|---|---|
| 1 | `getProperties().visible === false` | line tool 属性树的通用字段，预期主路径 |
| 2 | `shape.getVisible() / isVisible()` | 若该版本在 shape 上暴露了 getter |
| 3 | `chart.getEntityVisibility(id)` | 老接口若尚在 |
| — | 全都取不到 → **视为可见** | 宁可多显示，也不能漏掉真实仓位 |

⚠️ 这条判定**未经真实数据验证**（TradingView 禁止匿名会话创建画线，见 7.1）。
面板左上角**圆点可点击 → 复制诊断信息**，内含每个 shape 的 `propKeys` / `visLike` / `resolved.via`，
一眼就能看出实际走了哪条路、属性名到底叫什么。

### 3.5 文字 + 图片一起进剪贴板（v1.4 新增）

**需求**：复制时图片不要下载成文件、也不要只记路径，要**跟着记录一起走**。

**做法**：剪贴板一次写入两种 MIME ——
`text/plain`（TSV，给记事本这类只认文本的场景）+ `text/html`（带 `<table>`，图片以
`<img src="data:image/png;base64,…">` 内嵌）。Excel / WPS 粘贴时优先吃 HTML，于是
**表格落位 + 图片进来**一次完成。

**实测（跨进程验证，2026-09-26）**：

| 检查点 | 结果 |
|---|---|
| 系统剪贴板格式 | 出现 `HTML Format` + `CF_UNICODETEXT` |
| HTML 内容 | 含 `<table>` ✓ `<img>` ✓ `data:image/png;base64,` ✓ |
| WPS 表格粘贴后 A1 | `时间`（表头落位） |
| B2 / E2 | `MGCZ6` / `312.59`（数据行落位） |
| UsedRange | `$A$1:$L$2`（12 列全识别） |
| Shapes | `1`，type=13（图片），270×180 |

**结论：不落盘也能把图带进表格，方案成立。**

**副作用（须知）**：图片在表格里是**浮动对象**，会盖在「截图」列上方。
每笔一张、纵向排列，视觉上正好对着各行；嫌乱可选中图片 Delete，数据行不受影响。

**结论：可行，核心路径已跑通。**

### 3.6 批量复制怎么取图（v1.5 新增）

**需求**：「复制全部」也要带图，不是只出纯文本。

**先试了最好的方案、失败了**：想让每笔截出**各自区域**的图（按工具的屏幕位置裁剪）。
实测发现 TradingView **网页版没开放坐标换算**：

| API | 实测结果 |
|---|---|
| `chart.priceToCoordinate` | `undefined` |
| `chart.timeToCoordinate` | `undefined` |
| `chart.coordinateToPrice` / `coordinateToTime` | `undefined` |
| `chart.timeScale` | `undefined` |
| `chart.getVisibleRange` | `function` ✅（但不足以反推坐标） |

只能拿到可见时间范围，无法把「某个价格 / 某根 K 线」换算成像素位置 → **逐笔裁剪做不了**。

**改用的方案**：`captureVisibleTab` **截一次**，多行**共用同一张图**。
语义上站得住：**同屏画出来的几个仓位，本来就是同一张画面**。

**顺手踩到的一个反直觉结论**（已实测，别再走回头路）：

| 处理 | 尺寸 | PNG 字节 |
|---|---|---|
| 裁剪后原图 | 1124×796 | **64,275** |
| 缩到宽 480 再编码 | 480×340 | 71,605 |

**缩小反而更大** —— TradingView 图表是大片纯色 + 细线，PNG 对这种内容压缩率极高；
缩放后的抗锯齿产生大量灰阶渐变，熵反而上去了。所以**不做缩放，直接用原图**，画质还更好。
（去掉缩放后，两个工具的批量剪贴板 HTML 从 191,826 字符降到 172,138 字符。）

**代价（须知）**：n 行就有 n 份重复的 base64（实测两张图 base64 完全相同）。
HTML 表格里没法引用同一份数据，这属于 HTML 粘贴的固有成本；10 笔约 0.8 MB，剪贴板扛得住。

## 6. 架构

```
TradingView 图表页
├─ MAIN world  tv-bridge.js ── 读 window.TradingViewApi → 算三价
│                  │ window.postMessage（{__tvrc:'TVRC', reqId}）
└─ ISOLATED world  content.js ── 悬浮面板（Shadow DOM）+ 点击复制 + 写剪贴板
                   │ chrome.runtime.sendMessage
                   ▼
      background service worker
      · chrome.tabs.captureVisibleTab → PNG
      · chrome.storage.local → 记录池（exported 标记）
                   ▼
      popup · 记录列表 / 复制未导出 / 列模板设置
```

### 关键技术点

| 点 | 做法 | 为什么 |
|---|---|---|
| **必须 MAIN world** | `content_scripts[].world = "MAIN"` | 默认 ISOLATED world **读不到** `window.TradingViewApi`。命门 |
| 跨 world 通信 | `window.postMessage` + `event.source === window` 校验 | 两个 world 唯一可靠通道；**不能用 secret 变量传递**（ISOLATED 读不到 MAIN 的 window 属性） |
| 面板隔离 | Shadow DOM | 防被 TradingView 全局 CSS 污染 |
| 截图裁剪 | 取「面积最大的 canvas」的 rect 作为图表区域 | 不依赖 TV 的 class 名，改版也不怕 |
| 隐藏过滤 | `getProperties().visible` 等多路兜底（见 3.4） | ILineDataSourceApi 无 `isVisible`，必须自己找 |
| 面板拖拽 | Shadow DOM 内 pointerdown/move + `chrome.storage.local` 记位置 | 避免面板挡住图表 |
| 剪贴板（富文本） | `ClipboardItem` 一次写 `text/plain` + `text/html`（图片 base64 内嵌）→ 兜底 `writeText` → 兜底 `execCommand` | Excel/WPS 优先吃 HTML，文字与图一次到位 |

## 8. 风险

| # | 风险 | 对策 |
|---|---|---|
| R1 | TV 改版导致 API 路径变化 | 多路径探测 + 面板「自检」 |

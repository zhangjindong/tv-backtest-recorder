# 发布到 Chrome 网上应用店 · 操作指南

> 面向第一次上架的情况写的，按顺序走一遍即可。

---

## 0. 先确认这三件事

| 检查项 | 状态 |
|---|---|
| 上传包 | `dist/tv-backtest-recorder-1.0.0.zip`（manifest 在压缩包**根目录**） |
| 商店图标 | `extension/icons/icon128.png`（128×128） |
| 屏幕截图 | `store/screenshots/01-*.png` ~ `04-*.png`（1280×800） |
| 顶部宣传图块 | `store/screenshots/marquee-1400x560.png`（1400×560，可选但推荐） |
| 宣传图 | `store/screenshots/promo-440x280.png`、`promo-920x680.png`（可选） |

---

## 1. 注册开发者账号（一次性，5 美元）

1. 打开 https://chrome.google.com/webstore/devconsole
2. 用**你的常用 Google 账号**登录（以后升级/改版都用它，别用临时账号）
3. 接受开发者协议，支付 **5 美元**注册费（一次性，不是年费）
4. 建议同时把「发布者名称」填好（会公开显示在商店页）

> 账号注册后，发布者名称**改起来很麻烦**，第一次就填成你想要长期用的。

---

## 2. 创建条目并上传

1. 开发者控制台 → **新增条目 / New item**
2. 上传 `dist/tv-backtest-recorder-1.0.0.zip`
3. 上传成功后会看到条目草稿，此时**不要直接提交**，先补完下面所有字段

---

## 3. 填写「商品详情 / Store listing」

对照 `01-商店列表文案-中文.md` 逐项粘贴：

| 后台字段 | 从哪抄 |
|---|---|
| 名称 | 中文文案 § 一 |
| 简短说明（132 字符） | 中文文案 § 二 |
| 详细说明 | 中文文案 § 三 |
| 类别 | 生产力工具 |
| 语言 | 中文（简体） |
| 商店图标 128×128 | `icons/icon128.png` |
| **顶部宣传图块 1400×560** | `screenshots/marquee-1400x560.png`（同目录另有 `.jpg`，二选一） |
| 屏幕截图（按顺序上传 1→4） | `store/screenshots/` |
| 小型宣传图 440×280（可选） | `screenshots/promo-440x280.png` |
| 大型宣传图 920×680（可选） | `screenshots/promo-920x680.png` |

> **顶部宣传图块**会出现在商店首页的横向轮播里，是**唯一能带来自然流量**的图片，建议一定上传。
> 规格硬要求：**1400×560**，JPEG 或 **24 位 PNG（不能带 alpha 透明通道）**。
> `marquee-1400x560.png` 已是 RGB 三通道无透明；若后台拒收 PNG，改传同目录的 `marquee-1400x560.jpg` 即可。

> 想同时上英文列表：在「语言」里再加 English，用 `02-...英文.md` 的内容填一遍。

---

## 4. 填写「隐私权规范 / Privacy practices」

这是**最容易被卡**的一步，务必逐项照抄 `03-权限理由与数据使用披露.md`：

1. **单一用途说明**（Single purpose）
2. **权限理由**：`storage`、`activeTab`、主机权限 —— 三个都要填
3. **是否使用远程代码** → **否**
4. **数据使用**：勾选「不收集任何用户数据」相关选项，其余全部**不勾**
5. **隐私政策 URL**：如果上面声明了「不收集数据」，可留空；
   想更稳妥就把 `04-隐私政策.md` 发布成一个公开网页（GitHub Pages 等）后填入

---

## 5. 提交审核

1. 确认「可见性」为**公开**，「定价」为**免费**
2. 点 **提交审核 / Submit for review**
3. 首次审核通常几天内出结果，可能收到「需要提供更多信息」的邮件

### 常见被拒/被问的原因（本扩展的应对）

| 审查疑问 | 我们的回答依据 |
|---|---|
| 为什么要「读取所有网站数据」这么宽的权限？ | 见 `03-...md` 的 `<all_urls>` 理由：Chrome 的截图 API 要求，且内容脚本只注入 tradingview.com |
| 单一用途不够聚焦？ | 一句话：把 TradingView 仓位工具的价格与截图，一键记录到 Excel |
| 是否违反品牌/商标？ | 名称用缩写「TV」，未使用全称；商店页不使用 TradingView 官方 Logo |
| 是否含远程代码？ | 无：零 `eval`、零外链脚本，全部代码在包内 |

---

## 6. 以后改版怎么发

```bash
# 1) 改代码
# 2) 把 manifest.json 的 version 加一（如 1.0.0 -> 1.0.1）
# 3) 重新打包
cd "D:\交易学习\TV回测插件"
# （用 build 脚本，见 README / dist 目录里的打包命令）
# 4) 开发者控制台 → 你的条目 → 上传新 zip → 提交审核
```

> 版本号只能加不能减；每次上传的版本号必须比上一版大，否则会被拒绝。

---

## 7. 想先小范围试？

在控制台把可见性设成 **不公开（Unlisted）** 或 **私享**，
只有拿到链接的人能装。验证没问题后再切成公开。
